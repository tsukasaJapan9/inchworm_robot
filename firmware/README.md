# 実機ファームウェア

学習した方策を M5Stack Core2 に載せて XL330 ×2 を動かす。

```
firmware/
  platformio.ini
  include/policy_weights.h   ← export_policy.py が生成（手で編集しない）
  src/main.cpp
```

## 中身

100 Hz で次を回すだけ。

```
IMU と Dynamixel から観測 14 個を作る
  → 正規化 → 14 -> Tanh(64) -> Tanh(64) -> 2 の MLP
  → 出力を「目標角の増分」として積分（1 ステップ 5 度まで）
  → Goal Position として XL330 に送る
```

方策は 5278 パラメータ・20.6 KB。ESP32 の SRAM に収まるので PSRAM も外部ストレージも要らない。

## 重みの書き出しと書き込み

```sh
cd sim
uv run python export_policy.py ppo_myrun_s0    # 既定の出力先が firmware/include/policy_weights.h
cd ../firmware
pio run -t upload
```

**`VecNormalize` の平均と標準偏差もヘッダに入る。** 方策の重みだけ移植すると観測の
スケールが合わず、まったく別の動きになるので注意。

## ⚠ 実機で必ず確認すること

`src/main.cpp` の先頭、**★ が付いた定数**を実機に合わせる。ここがシミュと違うと方策は別物になる。

| 定数 | 何を入れるか | 確認方法 |
|---|---|---|
| `ID_FRONT` / `ID_REAR` | サーボの ID | Dynamixel Wizard かスキャン |
| `DXL_BAUD` | 通信レート | サーボ側の設定と合わせる |
| `PIN_DXL_RX/TX/DIR` | UART のピン | 駆動基板の結線。基板が方向制御を自動でやるなら DIR は -1 |
| `SIGN_FRONT/REAR` | 持ち上げる向きを + にする符号 | +10 度を送って**先端が持ち上がる**まで符号を変える |
| `CURRENT_LIMIT_MA` | 電流上限 | 最初は 400mA 程度から。方策のトルク実効値は 359mA 相当 |
| `MapImu()` | IMU の軸 → 機体座標（x=前, y=左, z=上） | 機体を前に傾けて `g_x` が正になるか見る |

## ゼロ点キャリブレーション（ボタン C）

実機は節を水平にしても Present Position が 0 度にならないので、**どこを水平とみなすかを
機体に覚えさせる**。

1. 待機中（トルクは切れている）に、**前後の節を手で水平にして押さえる**
2. **ボタン C** を押す
3. そのときの Present Position を 16 回読んで平均し、ゼロ度として **NVS に保存**する
4. 画面とシリアルに `[calib] saved home=(..., ...) deg` が出れば完了

**電源を切っても残る**ので、やり直すのは機体をばらしたときだけでよい。
**校正前はボタン A を押しても走らない**（ゼロ点が分からないまま動かすと最初の 1 ステップで機体が飛ぶ）。

## 立ち上げ手順（この順でやる）

**いきなり方策を走らせない。** 下から順に確かめる。
待機中は画面に `q`（関節角）と `g`（重力方向）が出続けるので、方策を動かさずに 1〜4 が確認できる。

1. **ビルドして書き込む。** シリアルに `[selftest] a[0]=... OK` が出れば、
   C の推論が Python と一致している（export 時のテストベクタと突き合わせている）
2. **`[dxl] id=1 ping=OK`** を確認。NG ならボーレート・ID・結線
3. **節を水平にしてボタン C**。そのあと手で前の節を持ち上げて、画面の `q` が
   **水平で 0、持ち上げると正**になるか見る。負になるなら `SIGN_FRONT/REAR` を反転する
4. **機体を手で傾けて `g` を見る**。水平静置で `(0.00, 0.00, -1.00)` 付近になるか。
   ならなければ `MapImu()` を直す
5. ここまで合ってから **ボタン A で方策を走らせる**。ボタン B でトルク OFF

## テレメトリ

ファームは USB シリアルに 1 行 1 サンプルで観測を流す（**待機中も流れる**）。
シリアルモニタ（`pio device monitor`）で直接読める。

```
T,<millis>,<ax>,<ay>,<az>,<gx>,<gy>,<gz>,<q1>,<q2>,<dq1>,<dq2>,<tgt1>,<tgt2>,<run>
   加速度[g]      角速度[rad/s]   関節角[deg] 関節角速度[rad/s] 目標角[deg] 走行中=1
```

送信レートは `TELEMETRY_DECIM` で間引く。上げたいときは `Serial.begin()` のボーレートと合わせて調整する。

## 安全

- 起動時はトルク OFF。ボタン A を押すまで動かない
- 目標角はソフト側で **±90 度**にクリップしている
- `CURRENT_LIMIT_MA` でトルクを制限している（Dynamixel 側の保護も効く）
- ループが 10ms に間に合わないと `over` カウンタが増える。増え続けるなら
  通信レートを上げるか、`getPresentVelocity` の読みを間引く

## うまく歩かないときに見るところ

| 症状 | 疑うところ |
|---|---|
| ボタン A で動かない | 未校正。節を水平にしてボタン C |
| 起動直後に暴れる | ゼロ点がずれている。節を水平にしてボタン C をやり直す |
| 片方の関節だけ逆に動く | `SIGN_REAR` の符号 |
| その場で固まる | 観測の正規化。`g_*` の軸か `q` の単位（rad か deg か）を疑う |
| シミュより明らかに遅い | サーボの kp と `armature`。`sim/env.py` の `DR_RANGES` に実機が入っているか確認する |
